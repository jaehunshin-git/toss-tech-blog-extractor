# 토스 기술 블로그 크롤러: 파싱 폴백 전략 가이드

이 문서는 `toss-tech-blog-extractor` 프로젝트가 HTML 구조 변경에도 게시글을 계속 추출하도록 구성한 방법을 설명합니다.

## 핵심 원칙: 의미 기반 파싱을 우선한다

`css-`로 시작하는 클래스 이름은 빌드 과정에서 바뀔 수 있으므로, 크롤링의 유일한 식별자로 사용하면 안 됩니다. 현재 구현은 다음 순서로 게시글을 파싱합니다.

- 제목: `<h1>` 요소, Open Graph 제목 메타데이터
- 날짜: `<time>`, 헤더의 `YYYY년 M월 D일` 텍스트, 페이지 데이터의 `publishedTime`
- 본문: 본문 CSS 선택자, 게시글 헤더 다음 콘텐츠 영역

## CSS 선택자는 본문 품질을 위한 보조 수단이다

본문의 코드 블록, 이미지, 문단 구조를 Markdown으로 변환하려면 전용 본문 컨테이너가 필요합니다. 기존 본문 CSS 선택자는 이 용도에 가장 정확하므로 첫 번째 본문 후보로 사용합니다. 선택자가 일치하지 않으면 헤더 뒤의 콘텐츠 컨테이너로 전환합니다.

## 목록 수집은 공개 API를 우선 사용한다

목록 페이지의 페이지네이션 UI는 변경될 수 있으므로, URL 수집은 공개 목록 API를 우선 사용합니다. API 요청이 실패하거나 응답 형식이 달라지면 기존 HTML 목록 수집 방식으로 자동 전환합니다.

## 유지보수 기준

사이트 구조가 바뀌면 `selectors.py`를 수정하고, 이전 구조·현재 구조를 모두 포함한 단위 테스트를 추가합니다. 네트워크 검증은 실제 게시글 하나와 목록 API 응답을 대상으로 정기적으로 수행합니다.
