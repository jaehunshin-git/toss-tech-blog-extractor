# 토스 기술 블로그 크롤러: CSS 선택자 전략 가이드

이 문서는 `Tech-Blogs-To-Threads-v2` 프로젝트의 토스 기술 블로그 크롤러, 특히 `toss_techblog_extractor.py`가 **왜 동적으로 생성되는 `css-` 접두사 클래스 이름을 선택자로 사용하는지**에 대한 기술적인 이유를 설명합니다.

---

## ❓ 핵심 질문: 왜 불안정한 `css-` 클래스 선택자를 사용하는가?

`css-`로 시작하는 클래스 이름은 프레임워크(예: Next.js)나 빌드 도구에 의해 자동으로 생성되므로, 웹사이트 코드가 업데이트될 때마다 쉽게 변경될 수 있습니다. 이렇게 불안정한 값을 크롤링의 핵심 식별자로 사용하는 것은 위험해 보일 수 있습니다.

그럼에도 불구하고 이 방식을 채택한 이유는 다음과 같은 현실적인 제약과 전략적 판단 때문입니다.

### 1. 안정적인 대안의 부재

웹 크롤링에서 데이터를 안정적으로 추출하기 위한 가장 이상적인 식별자는 다음과 같습니다.

- **고유 ID**: `id="article-body"`
- **의미 있는 클래스명**: `class="post-content"`
- **HTML 시맨틱 태그**: `<article>`, `<main>` 등

하지만 토스 기술 블로그의 페이지 소스를 분석해보면, **본문, 제목, 날짜 등 핵심 콘텐츠 영역을 명확하게 구분할 수 있는 위와 같은 안정적인 식별자가 존재하지 않습니다.**

모든 요소가 동적으로 생성된 `css-` 클래스 이름으로만 구성되어 있어, 개발자에게는 다른 선택지가 없습니다.

### 2. 차선책으로서의 선택

안정적인 대안이 없는 상황에서, 동적 클래스 이름은 **현재 시점에서 해당 요소를 유일하게 식별할 수 있는 차선책**입니다. 크롤러는 어떻게든 데이터를 가져와야 하므로, 비록 불안정하더라도 현재 사용 가능한 유일한 식별자를 사용할 수밖에 없습니다.

### 3. 위험 완화 전략: `*=` 선택자 사용

개발자는 이 불안정성을 조금이라도 완화하기 위해 다음과 같은 전략을 사용했습니다.

```python
# class="css-vf4rrt" 가 아닌 class*="css-vf4rrt" 사용
'title': 'h1[class*="css-vf4rrt"]'
```

`=` (정확히 일치) 대신 `*=` (문자열 포함) 선택자를 사용함으로써, 클래스 목록에 다른 클래스가 추가되더라도 (예: `class="css-vf4rrt another-class"`) 선택자가 계속 작동할 수 있도록 최소한의 유연성을 확보했습니다.

### 4. 유지보수 비용의 감수

이러한 접근 방식은 **"크롤러는 언젠가 깨질 수 있다"**는 것을 전제합니다. 토스 기술 블로그의 프론트엔드 구조가 변경되면 이 선택자들은 더 이상 작동하지 않을 것입니다.

따라서 이 크롤러는 **지속적인 모니터링과 유지보수가 필요**하며, 이는 웹 크롤링 프로젝트의 본질적인 부분이기도 합니다.

## ✅ 결론

- **어쩔 수 없는 선택**: 안정적인 식별자가 없어서 유일한 방법인 동적 클래스 이름을 사용했습니다.
- **위험 완화**: `*=` 선택자로 약간의 유연성을 추가했습니다.
- **유지보수 필요**: 웹사이트 변경 시 선택자 업데이트가 필수적입니다.
